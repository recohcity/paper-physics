# paper-trebuchet 反向审计报告

审计对象：`recohcity/paper-trebuchet`（读取了 physics.js、trebuchet.js、main.js、textures.js、environment.js、audio.js）
审计依据：`references/audit-checklist.md`　工具：`scripts/mech2d.mjs`、`sweep_trebuchet.mjs`、`search_fix.mjs`

## 结论

1. 项目是**演示级**实现：投石臂运动和发射速度/仰角由经验公式给出，只有球的飞行和木块碰撞走物理引擎。作为叙事演示成立，但不能用来验证机构设计。
2. 用项目**自己的数值**（球 0.20 kg、臂长 0.62 / 0.185 m、配重 0.30–1.00 kg）做刚体解算，机构**推不动这颗球**。这不是调参问题，是质量比和杠杆比的结构性问题。
3. 项目同时使用了三套互相矛盾的尺度。
4. 存在可行的修改方案，已由解算器验证（见下文）。

## 更新（2026-09-28 续）：V3 运行期同步与实现层采样偏差

### 事件与根因

修复 V2 后用户实测默认档（UI 配重 2.60 kg、球 0.45 kg、拉角 85°）点 Fire，臂卡在拉满位不释放，"像球比配重箱重很多、碗左右下摆"。根因是**构造时序 bug**：`createMechanism()` 用物理构造默认（1.0 kg）创建配重 body，构造流程从未调用 `setCwMass()`——UI 显示的 2.60 只是滑块表面值（仅 input 事件才同步物理）。机构实际以 1.0 kg 配重对 0.45 kg 球运行，球端力矩压过配重端，静力学反转。**这不是 M2（静态平衡）在启动位的失败，而是"Spec/UI 声明值与运行期 body 参数脱节"——审计时只查了"机构能不能平衡"，没查"声明的量是否真的进了物理"**。

修复：构造 `createMechanism()` 后立即 `physics.setCwMass(counterweightKg)`。

### 前台验证（修复后）

| 采样 | arm 角 | omega | released |
|---|---|---|---|
| 释放轨迹 | 0.15 → -0.74 → **-1.00** | -5.45 rad/s | true |

默认档实测 **3.53 m/s / 31° / down 1–4（多轮）**；与 skill 金标准（rigid 3.296 / cannon 3.297，0.04% 差，AGREE）对照为 **+6.8%**。

### +6.8% 差异定位：实现层采样精度，非机构错误

逐项核对前端与金标准：机构参数（臂长/厚度/密度/杯/销轴/悬吊/盒尺寸）、body 质量与惯量（_applyInertia 手设）、铰链配置（前 5 方程启用 + motor 显式关）、solver（50 iter / 1e-7）、配重质量（setCwMass 后 body.mass=2.6）——**全部一致**。剩余差异归因：前端在 **60 Hz rAF 帧**上做释放角插值（omegaRelease 线性插值），金标准在 **240 Hz 固定步进**上无插值精确检测释放角——帧采样在释放角越过的 1/60 s 内高估 omega。**教训：交叉验证 5% 门槛适用引擎实现 vs 解算器（cannon_trebuchet.mjs vs mech2d.mjs）；前端 UI 实测值存在 ±7% 级采样偏差，应另立基准或提高采样（用固定步长状态而非 rAF 帧）**。

### 排查排除项

| 怀疑 | 结论 |
|---|---|
| 配重质量误同步 | 排除：setCwMass 已同步 mass+惯量 |
| 铰链 motor 误激活 | 排除：equations 前 5 启用 + motor 显式关 |
| gravityScale 未生效 | 排除：未设置 |
| solver 配置弱 | 排除：50 iter / 1e-7 与金标准一致 |
| 后台标签 rAF 冻结 | **确认为测试假象**：visibilityState=hidden 时 world.time/渲染帧停走（world.time=0、renderer.frame 恒定），"臂不动"是假象非代码问题；切回前台标签后正常。已入 `physics-pitfalls.md` 第 15 条 |

### 交互层通用经验（已抽象入 skill，非投石机特有）

1. **任何"示意/标注/热点"的位置必须取自渲染 mesh 的世界坐标**——手写近似坐标在改相机或改模型后必然失焦（T1）。
2. **标签布局是可验证的确定性算法问题**——包围盒碰撞外推、曲线采样交叉检测、同列垂直链检测；用户对"名称/位置/方向/曲率"的迭代微调用"特判 + 通用算法"组合承接（T2）。
3. **演示步骤的"完整播放"要有显式终止判据**（轮询出界/静止），固定 sleep 会在球落地时提前截断（T3/pitfalls 17）。
4. **步骤间不泄漏状态**——终态步骤静态化，否则上一帧动画被误读为"机器自己动了"（T4）。
5. **场景装饰物只要可能被交互对象碰到，就必须有真实碰撞体**，尺寸/位姿从 mesh 推导，碰撞组与机制 body 隔离（T5/pitfalls 16）。

### 局限

- 标注布局的视觉验收仍靠人工截图判断（无自动断言）；布局参数（dist/角度步长/阈值）是本案例调出的经验值，新案例需重标定。
- S7 完整回放上限 24s 是安全阀，慢镜下若球长时间滚动未静止会以超时结束（可接受）。
- 铅笔/橡皮碰撞体为 Box 近似圆柱/圆角，碰撞面略大于视觉，未做精确贴合。

### 交互层通用经验（新增，已抽象入 skill）

6. **纯装饰机构（绳索/卷筒/铰盘/指针）必须与动力学解耦**——不传力、不带碰撞，运动由真实状态的解析映射驱动（角度→绳长/旋转/方向符号）；改动装饰件不得改变任何发射读数（T6/pitfalls 21）。
7. **任何起点与机体重叠的发射物都需要分段碰撞激活**——慢镜/大步长下 solver 会把重叠物钳速至零，回放"秒退"；在最慢时间尺度下验证（P7/pitfalls 22）。
8. **低速滚动物体永不 settle——事件驱动优于速度阈值**：首次碰撞事件起固定时长兜底，通用超时仅作最后保险（T3/pitfalls 23）。

### 局限

- 卷筒铰盘旋转速度与摆杆角速度的比例（含绳长几何）仍为视觉近似，未做精确绳长-角度解析（纯装饰件，可接受）。
- 全场景阻挡中，球架托盘/卷筒细节仍为 Box 近似碰撞体，与视觉轮廓有微差。
- 演示档（6.0/0.60）与默认档（4.8/0.45）分离为叙事参数，需在文档中持续声明，避免被误当交互默认。
